# Decision log

Design reasoning lives in the [ADRs](https://github.com/julie-ng/ai-native-sdlc/tree/main/architecture/decisions) of the parent repo. This log covers infrastructure choices.

## Decisions

Rows retain decision history. The later choices below supersede the initial four-module/two-pool layout, suffixed identities and cluster resource groups. Runtime verification is tracked separately in the README.

| Date | Decision | Why |
|---|---|---|
| 2026-10-23 | Switch to Azure CNI Powered by Cilium (`network_data_plane` and `network_policy` = `cilium`) in place on the deployed, unused cluster | Needed to enforce the agents IMDS NetworkPolicy ([#4](https://github.com/julie-ng/ai-native-sdlc-infrastructure/issues/4)). Human decision to test in place while the cluster is unused. Microsoft's recommended engine; free without Advanced Container Networking Services; replaces kube-proxy. Trade-offs: all pools reimage at once and policies only enforce after; `cilium` → `azure` forces cluster replacement (azurerm v5.10.0 `internal/services/containers/kubernetes_cluster_resource.go`); `ipBlock` can't select pod or node IPs. Supersedes "no network policy engine". [Cilium on AKS](https://learn.microsoft.com/en-us/azure/aks/azure-cni-powered-by-cilium), [in-place update](https://learn.microsoft.com/en-us/azure/aks/update-azure-cni#update-the-data-plane-to-azure-cni-powered-by-cilium). |
| 2026-10-23 | Block IMDS (`169.254.169.254/32`) from `agents` with a NetworkPolicy allowing all other egress | Any non-hostNetwork pod can otherwise get tokens for every identity on its node (kubelet: `AcrPull` on the whole public registry; add-on identities). Least privilege on node identities is a convention; this keeps ADR-003 independent of it. Human decision: `agents` only, the one namespace running LLM-driven code. Enforces: no IMDS from non-hostNetwork agent pods. Does not restrict other egress, pod-to-pod traffic, or other namespaces. [#4](https://github.com/julie-ng/ai-native-sdlc-infrastructure/issues/4), [ipBlock limitation](https://learn.microsoft.com/en-us/azure/aks/azure-cni-powered-by-cilium#why-is-traffic-being-blocked-when-the-networkpolicy-has-an-ipblock-that-allows-the-ip-address). |
| 2026-10-23 | Pod Security Admission on `agents`: enforce `baseline`, warn and audit `restricted`; version `latest` | Cilium doesn't apply policies to hostNetwork pods, and privileged pods can rewrite node networking. `baseline` rejects both. Rejects Docker-in-Docker builds; rootless builders still work. `restricted` warnings show what agent templates need before enforcing it. Unpinned version follows the cluster's Kubernetes version. [PSA on AKS](https://learn.microsoft.com/en-us/azure/aks/use-psa), [Pod Security Standards](https://kubernetes.io/docs/concepts/security/pod-security-standards/). |
| 2026-10-23 | Not using the AKS IMDS restriction (preview) | Container Insights is an unsupported add-on; enabling fails while it's installed. Also blocks Azure Policy, application routing, Flux, Azure Backup and cost analysis; doesn't cover hostNetwork pods; needs a reimage to toggle; no azurerm v5.10.0 argument. [IMDS restriction](https://learn.microsoft.com/en-us/azure/aks/imds-restriction). |
| 2026-10-22 | Expose a separate root `cluster` output for kubecontext and start/stop commands | Human deployment confirmed targeted cluster apply leaves the combined `summary` absent because it also depends on the unapplied Kubernetes module. Avoid that bootstrap dependency; fail before calling Azure if cluster output is missing. [Terraform targeting caveats](https://developer.hashicorp.com/terraform/cli/commands/plan#resource-targeting). |
| 2026-10-22 | Add `make start-cluster` / `make stop-cluster` wrappers around Azure CLI | Human-requested POC idle-cost controls. Read target names from local Terraform outputs and fail before calling Azure if outputs are missing. No stored IDs, automatic scheduling or extra scaling services. Human confirmed stop succeeds; start/restart remains unverified. [AKS stop/start](https://learn.microsoft.com/en-us/azure/aks/start-stop-cluster). |
| 2026-10-22 | Retain human-selected D2s v5 / minimum 1 system pool for this POC | Human explicitly chooses to proceed with this sizing despite published system-pool guidance. Human reported successful provisioning on 2026-10-22; workload behavior remains untested. |
| 2026-10-22 | POC monitor collection: logs/events preset, pod inventory every 5 minutes, events/inventory limited to platform namespaces | Reduce ingestion from the original 12 streams. Keep stdout/stderr and non-Normal events; omit historical performance/extra inventory and accept reduced portal visualizations without adding Prometheus. [Microsoft cost guidance](https://learn.microsoft.com/en-us/azure/azure-monitor/containers/container-insights-cost), [stream settings](https://learn.microsoft.com/en-us/azure/azure-monitor/containers/kubernetes-monitoring-enable#configuration-options). |
| 2026-10-22 | Agent ConfigMap excludes system/default namespace logs, disables environment-variable collection, and keeps only non-Normal Kubernetes events | DCR namespace filtering does not filter stdout/stderr. Apply the Kubernetes stage before workloads. New namespaces require review of this exclusion list; existing agent output remains collected. [Microsoft agent config](https://github.com/microsoft/Docker-Provider/blob/ci_prod/kubernetes/container-azm-ms-agentconfig.yaml), [filtering methods](https://learn.microsoft.com/en-us/azure/azure-monitor/containers/kubernetes-data-collection-configure). |
| 2026-10-22 | Keep 30-day workspace retention; add a 0.1 GB/day workspace ingestion cap | Initial POC backstop, not measured sizing or a hard spending ceiling. Overshoot is billable; reaching the cap creates collection gaps until reset. Retention under 31 days does not save Analytics ingestion costs. [Daily cap](https://learn.microsoft.com/en-us/azure/azure-monitor/logs/daily-cap), [retention](https://learn.microsoft.com/en-us/azure/azure-monitor/logs/data-retention-configure). |
| 2026-10-22 | POC keeps minimum 1 and maximum 2 on every pool; defer user-pool scale-to-zero | Human decision: use [AKS cluster start/stop](https://learn.microsoft.com/en-us/azure/aks/start-stop-cluster) when idle rather than adding application wake-up infrastructure. Scale-to-zero remains a [target design, #3](https://github.com/julie-ng/ai-native-sdlc-infrastructure/issues/3). |
| 2026-10-22 | Three pools: `system` and `platform` use D2s v5; `agents` uses D4s v5; all autoscale 1–2 nodes | Human decision: smaller HTTP platform services, more capacity per agent node. Agent nodes have `workload=agents:NoSchedule`; workload manifests select their pool. Scheduling separation is not a security boundary. System D2s/minimum 1 was accepted in the human deployment; published guidance differs in [current system-pool requirements](https://learn.microsoft.com/en-us/azure/aks/use-system-pools). [AKS node pool placement](https://learn.microsoft.com/en-us/azure/aks/use-multiple-node-pools). |
| 2026-10-22 | Name cluster resource groups `{name}-cluster-rg` and `{name}-aks-managed-rg`, without random suffixes | Human decision: resource group names require subscription-level uniqueness only. Azure creates the managed node group. Changing either group name after AKS deployment requires cluster replacement. [Azure naming rules](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/resource-name-rules#microsoftresources), [pinned provider](https://github.com/hashicorp/terraform-provider-azurerm/blob/v5.10.0/website/docs/r/kubernetes_cluster.html.markdown). |
| 2026-10-22 | Name platform service identities `{service}-mi` | Human decision: `workload` is redundant in the resource name; retain each service name and the managed identity type suffix. |
| 2026-10-22 | Remove the deployment suffix from all managed identity names and the identities module inputs | Human decision: identity names only need uniqueness within their resource group. Supersedes suffix retention for identities in the module split below. [Azure naming rules](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/resource-name-rules#microsoftmanagedidentity). |
| 2026-10-22 | Add persistent `identities` module and resource group before `cluster`; protect principals with `prevent_destroy` | Preserve principals and role assignments on shared resources across cluster rebuilds. Federation and cluster-scoped RBAC stay in `cluster`. Retain the deployment suffix. Existing identities require migration review. [AKS identity lifecycle](https://learn.microsoft.com/en-us/azure/aks/managed-identity-overview), [Terraform refactoring](https://developer.hashicorp.com/terraform/language/modules/develop/refactoring). |
| 2026-10-22 | One environment, `dev`; base name `ai-sdlc`, no env in names; remove hyphens for storage/ACR | POC. |
| 2026-10-22 | Initial layout, superseded by the identities split: one root calling four modules: networking, shared, cluster, kubernetes. Applied one at a time with `-target` | Staged rollout while testing; one state. Replaces the earlier separate-repo split. |
| 2026-10-22 | Local state | Blind first pass; remote backend later. |
| 2026-10-22 | Azure CLI auth only; no user, tenant or subscription IDs in the repo | Deployer identity from `data.azurerm_client_config`, Postgres admin UPN via `data.azuread_user`. Subscription from `az account set` — azurerm v5.10 requires `subscription_id` only when `use_cli = false` (`internal/provider/provider.go`). Adds the `azuread` provider for one lookup. |
| 2026-10-22 | `westeurope` for everything except monitoring; Log Analytics + Container Insights DCR pinned to `northeurope` in code | Chosen by the human developer. No extra variable — the two monitoring resources hard-code the region with a comment. The DCR must be in the workspace region. |

Accept a database in a different region from AKS. Human later confirmed successful server creation in North Europe; see [Azure regional restrictions](https://learn.microsoft.com/en-us/azure/postgresql/troubleshoot/how-to-resolve-capacity-errors). |

| 2026-10-22 | Terraform creates ServiceAccounts; Helm charts reference them by name | Federated credential subjects are then fixed by this repo, not by chart defaults. |
| 2026-10-22 | ACR pull only | Images are built and pushed manually. No identity in this repo, the cluster or GitHub gets push. |
| 2026-10-22 | No Managed Prometheus or Grafana | Cost. Container Insights + Log Analytics only. |
| 2026-10-22 | Key Vault CSI driver add-on on, secret rotation enabled | Secrets as mounted files ("credentials as files, never env vars", ADR-006). |

| 2026-10-22 | Agents receive artifacts as user delegation SAS URLs, scoped per blob and per permission | Signed with the artifact service's Entra credentials (Storage Blob Delegator at account scope), so shared keys stay off. ## Accepted trade-offs

| Trade-off | Notes |
|---|---|
| PostgreSQL uses a public endpoint | TLS and firewall rules apply. Azure-to-Azure public endpoint traffic can remain on the [Microsoft backbone](https://learn.microsoft.com/en-us/azure/networking/microsoft-global-network); public endpoint is not synonymous with public-internet routing. |
| Dedicated agent pool adds a third always-on node in the POC | Minimum one node per pool. User-pool scale-to-zero is deferred; cluster start/stop is the POC approach when idle. |
| No egress filtering | Agents can reach any destination except IMDS, including every pod in the cluster. Firewall subnet is reserved. |
| `-target` for staged applies | Terraform warns against routine use. Final untargeted plan should show no changes. |
| ACR on public endpoint | Basic SKU has no network rules; private endpoints need Premium. |
| Storage LRS, Postgres Burstable, no HA | Cost. |
| `argo` storage account unused by agent steps in the POC | Only the Argo controller and server identity has access. Workflow templates must not set `archiveLogs` or output artifacts on agent steps, or the executor fails to upload. |
| Agent step logs outlive the pod only via Container Insights | DCR collects `ContainerLogV2`; the agent excludes system/default namespace logs. Agent stdout/stderr remains collected with 30-day retention, subject to the workspace daily cap and collection gaps. |
| Non-expiring Kubernetes token in agent pods' executor containers | Legacy ServiceAccount token Secret, as Argo requires. Allows only `create` / `patch` on `workflowtaskresults` in `agents`. Not mounted into `main`. |

## Not carried over from cloudkube

Inherited patterns dropped, with reason:

| Pattern | Why dropped |
|---|---|
| Separate repos per lifecycle | Single root with modules, per this repo's brief. |
| `provider` blocks inside modules | Modules declare `required_providers` only. |
| Kubelet VM Contributor / Managed Identity Operator on resource groups | Not needed; control plane gets Managed Identity Operator on the kubelet identity only. |
| Vnet-integrated API server subnet | Default public endpoint chosen. |
| NGINX ingress, TLS certs, DNS zone | Out of scope. |
| Node SSH key (`linux_profile`) | Not needed. |
